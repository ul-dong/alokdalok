# 수익화 설계 (MONETIZATION)

2026-11-15 · 사용자 결정을 전제로 쓴 판단 문서. 규칙의 근거 문서는 `docs/MASTER_PROMPT.md` 절대 원칙이고, 이 문서는 그 규칙을 어떻게 지키며 돈을 벌지를 정한다.
코드는 기능 플래그 `lib/core/features.dart` `kBillingEnabled = false`로 꺼진 채 들어가 있다(8절).

## 1. 배경과 방향

**한국 Play 무료 출시만으로는 수익이 거의 없다.**
유아 교육 앱 검색 상단은 대형 IP가 잡고 있고, 새 앱은 리뷰 0에서 시작해 노출이 사실상 없다.

**광고는 넣지 않는다 (영구).**
- 만 3세 단일 타겟이면 Google Play 가족 정책상 자체 인증 광고 SDK만 쓸 수 있고, 맞춤 광고가 금지된다.
- 전면 광고, 5초 안에 못 닫는 보상형, 한 화면에 여러 광고, 콘텐츠와 구분 안 되는 광고가 모두 금지라 남는 것은 작은 배너 하나다.
- 비맞춤 광고라 단가가 낮고, 3세는 배너를 반드시 눌러 브라우저로 나간다.
- release 앱은 INTERNET 권한이 없는 완전 오프라인 앱이다. 광고를 넣으면 이 강점이 깨지고 AD_ID 문제까지 생긴다.

**돈이 될 가능성이 있는 길 (우선순위대로)**

| 순위 | 길 | 왜 |
|---|---|---|
| 1 | **해외 출시** | 음성이 문장 조각 이어 붙이기라 언어 하나 더하는 비용이 싸다(영어 976문장 녹음 끝). 그림은 전부 CustomPainter라 라이선스 걸림이 없다. 서버가 없어 운영비가 0이다. 가장 큰 레버리지 |
| 2 | **기관 B2B** (어린이집·유치원) | 광고 없음, 오프라인, 놀이 시간 제한, 눈 보호가 그대로 영업 문구다. 개인 결제보다 단가가 높다 |
| 3 | **포트폴리오** | 가장 확실한 수익원. 기술 문서화(이 문서, `RELEASE.md`, `GAP_REPORT.md`)가 곧 자산이다 |

개인 과금(이 문서의 1회 해금)은 위 셋을 받쳐 주는 **보조 수단**이다. 해외 스토어에서도 같은 상품 하나로 판다.

## 2. 수익 규칙 (영구 규칙 + 허용 범위)

| 규칙 | 기간 | 코드에서 지키는 곳 |
|---|---|---|
| 광고 금지. 광고 SDK·AD_ID 없음 | 영구 | 의존성 없음, 매니페스트 `AD_ID tools:node="remove"`, `test/release_test.dart` |
| 확률형 뽑기(가챠) 금지 | 영구 | 상점은 고른 물건을 정해진 코인 값에 산다 |
| 코인 현금 판매 금지. 코인은 놀이로만, 틀려도 차감 없음 | 영구 | 해금 코드(`entitlement.dart`, `billing_store.dart`)는 코인을 모른다. 코인으로 해금을 사는 길도, 돈으로 코인을 사는 길도 없다(`test/billing_test.dart` "코인으로 결제하는 길은 없다") |
| 구독 금지 | 영구(바꾸려면 사용자 결정) | 비소모성 상품 1종만 (`Entitlement.productId = 'full_unlock'`) |
| 1회성 전체 해금만 허용 | | 부모 확인 뒤 부모용 화면에서만. 아이 화면에는 가격·결제 버튼·배지 없음 |

## 3. 무료 범위와 해금 범위 (확정)

실제 데이터: `data/stages.dart` 숫자 8단계, 색깔·모양·크기·짝 맞추기 각 5단계(짝 맞추기는 한 판 3장).
`data/item_catalog.dart` 17테마 71개(합계 1,855코인), `data/vehicles.dart` 탈것 7종(합계 275코인), 색칠은 탈것마다 색당 10코인.

| | 무료 | 1회 해금 |
|---|---|---|
| 숫자 놀이 | **1~3단계** (한 가지 물건을 줄 맞춰 세기 단계 전부) | 4~8단계 (섞인 물건 중 한 가지만 세기) |
| 색깔 놀이 | **1~2단계** | 3~5단계 |
| 모양·크기·짝 맞추기 | **각 1단계** | 각 2~5단계 |
| 꾸미기 옷 | **로봇 테마 5개** (상점 첫 탭, 145코인) | 나머지 16테마 66개 |
| 탈것 | **열기구 1대** (20코인) + 그 탈것의 색칠·스티커 | 나머지 6대 |
| 친구 24마리, 스티커, 첫 색 | 모두 무료 | (해금 대상 아님) |
| 눈 보호·놀이 시간·백업·언어 | 모두 무료 | (해금 대상 아님. 아이 안전 기능은 절대 돈 뒤에 두지 않는다) |

**제안에서 바꾼 점: 탈것 1대(열기구)를 무료에 넣었다.** 제안대로 "탈것 전체 = 해금"이면 무료 사용자는 탑승·스티커·색칠을 한 번도 못 해 본다.
가장 싼 열기구 한 대만 열어 두면 앱의 핵심 고리(놀이 → 코인 → 사서 타고 꾸미기)를 무료로 다 겪는다.

**코인 경제와의 관계**
- 무료 범위에서 코인을 쓸 곳은 로봇 옷 145 + 열기구 20 + 열기구 색 최대 50 = **215코인**이다.
  무료 단계 8개를 처음 깨며 받는 보상(한 판 약 13코인 + 새 단계 5 + 첫 판 5)으로 대략 열몇 판, 20~30분 놀면 다 산다.
  그 뒤로도 코인은 계속 쌓이고 줄지 않는다. 해금하면 모아 둔 코인으로 바로 다른 옷·탈것을 산다.
- **잠긴 물건을 코인으로 사려 할 때:** 칸에는 가격 대신 자물쇠 그림만 보인다. 눌러도 입어 보지 않는다(사고 싶게 만드는 미리보기를 하지 않는다).
  사기 버튼 자리에는 큰 자물쇠와 "부모님께 보여 주세요"만 있고, 누르면 부모 확인 → 부모용 화면이다.
  `GameState.purchase/buyVehicle`은 코인이 많아도 `PurchaseResult.locked`를 돌려주고 코인을 빼지 않는다.
- 코인이 모자랄 때는 지금처럼 "놀이하면서 코인을 모아요"와 진행 막대만 보인다. 결제 화면으로 보내지 않는다.

**기존 사용자 보호 (결제를 켜는 업데이트 때)**
1. **이미 산 옷·탈것·색은 해금과 상관없이 계속 입고, 타고, 꾸미고, 색칠한다.** 잠금은 "아직 안 산 것을 코인으로 사기"에만 걸린다.
2. **결제가 처음 켜진 실행에서 그때 열려 있던 단계를 기억한다** (`SaveData.keepStages`, 저장 v10). 그 단계까지는 해금 없이 계속 논다.
   업데이트 시점이 아니라 "결제가 처음 켜진 실행" 기준이라, 플래그가 꺼져 있는 동안 더 깬 단계도 지킨다.
3. 깬 기록(별, 골인 길)은 그대로다. 무료 범위 위의 단계를 깨도 진행은 기억하지만 "새 단계가 열렸어요"라고 하지 않는다. 해금하면 그 진행까지 바로 열린다.
4. 모은 코인은 하나도 줄이지 않는다.
5. "기록 지우기"를 해도 산 해금과 지켜 준 단계는 지우지 않는다(기록이 아니라 권리).
6. 백업 글자에는 지켜 준 단계를 넣는다(기기를 바꿔도 지킨다). 산 해금은 넣지 않고 스토어 복원으로 옮긴다(6절).

|---|---|---|

| Google Play 미국 | **$3.99** | 세금 별도 표시 |
| 그 밖의 나라 | Play·App Store의 자동 환산(미국 기준) | 해외 출시 때 나라별로 다시 본다 |

- 앱은 가격을 하드코딩하지 않는다. 스토어가 준 현지 글자(`ProductDetails.price`, 예: "₩4,900", "$3.99")를 그대로 보여 준다.

## 5. 결제 입구와 아이 화면 규칙

입구는 두 곳뿐이고, 둘 다 `openUnlock(context)` → `confirmParent(context, force: true)`(덧셈 문제) → `UnlockScreen`을 지난다.

1. **설정 화면** 맨 위 "전체 놀이 열기" 칸 (결제가 켜졌을 때만 보임). 설정 자체도 부모 확인 뒤지만,
   부모님이 설정에서 부모 확인을 꺼 두었을 수 있어 결제 화면 앞에서는 **항상** 다시 묻는다.
2. **단계 고르기의 잠긴 단계** (그리고 상점의 잠긴 물건 자리의 자물쇠). 해금이 필요한 단계를 누르면 놀이를 시작하지 않고 부모 확인으로 간다.
   무료 범위 안의 "아직 안 깬" 단계는 예전처럼 흔들리며 "앞 단계를 먼저 놀아 볼까요?"라고 말한다.

**아이 화면 금지 목록**: 가격, 결제·구매 글자, "프리미엄"·"PRO" 같은 배지, 반짝이는 유도 효과, 결제를 말하는 음성.
아이 화면에는 기존 자물쇠 그림(`BigLock`)만 보인다. 부모용 화면은 글자로만 쓰고 음성을 내지 않는다.
부모용 화면은 `EyeScreen.parent`라 떠 있는 동안 눈 지킴이 카메라도 끈다.

## 6. 영수증 검증: 서버 없이 로컬 신뢰 + 로컬 캐시

**동작**
- 스토어가 알려 준 `purchased`/`restored`를 그대로 믿고, `SaveData.unlocked = true`를 기기에 저장한다.
- 앱을 열면 저장값을 먼저 믿는다. 스토어 연결은 뒤에서 조용히 하고, 실패(오프라인·스토어 앱 없음·플러그인 오류)해도 캐시대로 동작하며 멈추지 않는다.
- 안드로이드는 결제를 받으면 바로 `completePurchase`(acknowledge)를 한다. 3일 안에 하지 않으면 Google이 자동 환불한다.

**한계 (알고 받아들인다)**
- 루팅·탈옥 기기에서 저장값(`SharedPreferences`)을 고치거나, 스토어 응답을 가로채는 도구로 해금을 흉내 낼 수 있다. 즉 **복제 가능**하다.
- 환불을 앱이 알 길이 없다. Play의 환불 취소 목록(Voided Purchases API)과 App Store 서버 알림은 서버가 있어야 받는다.
  그래서 환불받은 기기에는 해금이 남을 수 있다(재설치하면 복원할 산 기록이 없어 잠긴다).

**그래도 서버를 두지 않는 이유**
- 이 앱의 핵심 약속이 "서버 없음, 회원가입 없음, 개인정보는 기기 안에만, 운영비 0"이다. 영수증 서버 하나가 이 약속과 1순위 전략(운영비 0 해외 출시)을 함께 깬다.
- 서버를 두면 구매 토큰과 기기 정보를 서버로 보내야 하고, 데이터 안전성 신고·개인정보처리방침·보안 책임이 생긴다(아동 대상 앱이라 부담이 크다).
- 상품이 ₩4,900짜리 1회 해금 하나다. 복제로 잃는 돈보다 서버를 운영하고 지키는 비용이 크다. 복제하는 사람은 원래 사지 않을 사람이다.
- B2B(2순위)는 스토어 결제가 아니라 기관 계약이라 이 검증과 상관이 없다.

## 7. 권한과 데이터 안전성 (release AAB에서 실측)

**실측 (2026-11-15):** `tool/build_android.sh --debug-signed`로 만든 release AAB(in_app_purchase 3.3.1 → in_app_purchase_android 0.5.5 → `com.android.billingclient:billing:9.1.0`)의
병합 매니페스트(`build/app/intermediates/merged_manifest/release/processReleaseMainManifest/AndroidManifest.xml`)와 AAB 안의 `base/manifest/AndroidManifest.xml`을 직접 확인했다.

| 항목 | 결과 |
|---|---|
| `android.permission.INTERNET` | **없음.** 결제 라이브러리 9.1.0의 매니페스트는 INTERNET을 요청하지 않는다. 앱의 `tools:node="remove"`(ML Kit datatransport용)도 그대로 둔다 |
| `com.android.vending.BILLING` | **추가됨** (billing 9.1.0이 넣는다, 정상) |
| `<queries>` | `com.android.vending.billing.InAppBillingService.BIND`, `com.google.android.apps.play.billingtestcompanion.BillingOverrideService.BIND` 추가 |
| activity | `com.android.billingclient.api.ProxyBillingActivity`, `ProxyBillingActivityV2` (exported=false) 추가 |
| `com.google.android.gms.permission.AD_ID` | **없음** (제거 규칙 유지) |
| 그 밖 (`CAMERA`, `ACCESS_NETWORK_STATE`) | 예전과 같음 |

**INTERNET 없이 결제가 되는 근거**
- Play 결제 라이브러리는 네트워크를 직접 쓰지 않는다. 기기의 Google Play 스토어 앱 서비스에 IPC로 붙고(위 `InAppBillingService.BIND` 쿼리), 결제 창·서버 통신·영수증은 Play 스토어 앱이 자기 권한으로 처리한다.
- 그래서 billing 라이브러리 매니페스트에 INTERNET이 없고, Google 결제 연동 문서도 요구하는 권한은 `BILLING`(라이브러리가 자동 추가)뿐이다.
- iOS StoreKit은 권한 개념이 없고 App Store 프로세스가 통신한다.
- **남는 위험:** 실기기에서 INTERNET 없는 앱으로 실제 결제(테스트 계정)를 아직 해 보지 않았다. 내부 테스트 트랙에서 확인한다(10절). 안 되면 그때 INTERNET 제거를 되돌리고 이 절과 `RELEASE.md` 5·7절을 고친다.

**플래그를 꺼 둔 지금도** 의존성 때문에 위의 BILLING 권한·queries·activity가 매니페스트에 들어간다(런타임에는 아무것도 하지 않는다).
결제를 켜기 전 출시에서 이것도 빼고 싶다면 `AndroidManifest.xml`에 `BILLING`을 `tools:node="remove"`로 지우면 된다(결제를 켤 때 다시 지운다).

**Play 데이터 안전성**: 결제를 켜는 출시 전에 다시 본다.
- 앱 자체는 여전히 아무것도 보내지 않는다. 기기에 남는 것은 "해금했는지" 참/거짓 하나다.
- 결제 정보(구매 기록·결제 수단)는 Google Play 결제 시스템이 Play 스토어 앱에서 처리한다. 이것을 앱의 "수집"으로 신고해야 하는지는 **Google 문서로 최종 확인 필요**(`RELEASE.md` 7.2).
- 가족 정책 선언의 "인앱 결제 없음"은 결제를 켜는 출시부터 "부모 확인 뒤 1회 인앱 결제 있음"으로 바꾼다. 스토어 등록 문구의 "인앱 결제 없음"도 함께 바꾼다.
- AD_ID 권한은 **절대 추가하지 않는다**. 광고 ID 선언은 계속 "아니요".

| 파일 | 하는 일 |
|---|---|
| `lib/core/features.dart` | `const kBillingEnabled = false`. `Features.billing`은 웹에서 항상 false. 테스트·미리보기만 `billingOverride` 또는 `Entitlement(enabled: true)`로 켠다 |
| `lib/services/entitlement.dart` | `Entitlement`(비소모성 1종, `unlocked`·`fullAccess`·`flow`·`price`, `start/refresh/buy/restore`), `FreeTier`(무료 범위) |
| `lib/services/billing_store.dart` | in_app_purchase 얇은 포장(`IapBillingStore`). 테스트는 가짜 스토어 |
| `lib/services/game_state.dart` | `unlockedStage` = min(깬 단계, 해금 범위), `progressStage`, `stageNeedsUnlock`, `itemLocked`, `vehicleLocked`, `PurchaseResult.locked`, `keepStages` 기록 |
| `lib/services/save_data.dart` | 저장 v10: `unlocked`(백업 제외), `keepStages`(백업 포함) |
| `lib/screens/unlock_screen.dart` | `openUnlock()`(부모 확인 강제) + 부모용 화면(ko/en ARB, 스토어 현지 가격) |
| `lib/screens/stage_picker.dart`, `lib/shop/` | 잠긴 단계·물건에 자물쇠, 누르면 `openUnlock` |
| `lib/screens/settings_screen.dart` | 결제가 켜졌을 때만 "전체 놀이 열기" 칸 |

**플래그가 꺼져 있으면(지금)**: `Entitlement.enabled = false` → `fullAccess`가 항상 true, `start()`가 바로 돌아와 `InAppPurchase.instance`를 만들지도 스토어에 연결하지도 않는다.
모든 단계·옷·탈것이 예전 그대로 열리고, 설정에도 결제 칸이 없다. 바뀌는 것은 저장 버전(v10, 값 2개 추가)과 위 7절의 매니페스트 항목뿐이다.

**웹**: in_app_purchase는 웹을 지원하지 않는다. `Features.billing`이 웹에서 항상 false라 웹 빌드는 언제나 전부 열림으로 동작한다.

## 9. 환불·기기 변경·재설치 때의 흐름

| 상황 | 흐름 |
|---|---|
| 결제 보류 (보호자 승인 대기, 현금 결제 수단 등) | 부모용 화면에 "결제 승인을 기다리고 있어요". 승인되면 스토어 알림으로 저절로 열리고 저장한다 |
| 결제 취소·실패 | 잠긴 그대로, 부모용 화면에 이유 한 줄. 코인·진행은 그대로 |
| 오프라인으로 앱 열기 | 저장된 해금 그대로 (스토어 연결 없이) |
| 재설치 (안드로이드) | 앱을 열 때 저장값에 해금이 없으면 뒤에서 조용히 `restorePurchases`를 한 번 한다. 같은 Google 계정이면 저절로 열린다 |
| 재설치 (iOS) | 복원이 Apple ID 로그인 창을 띄울 수 있어 저절로 하지 않는다. 부모님이 부모용 화면에서 [구매 복원] |
| 기기 변경 | 진행·옷·코인·지켜 준 단계는 설정의 백업 글자(ALOK1-)로, 해금은 새 기기 부모용 화면의 [구매 복원](안드로이드는 자동)으로. 같은 스토어 계정이어야 한다. 안드로이드 ↔ iOS는 스토어가 달라 해금이 옮겨지지 않는다(다시 사야 한다고 부모용 화면·스토어 설명에 적는다) |
| 환불 | 서버가 없어 앱이 알 수 없다. 그 기기에는 해금이 남는다. 재설치·기기 변경 뒤에는 복원할 기록이 없어 잠긴다 (6절 한계) |
| 기록 지우기 | 진행은 지우고 해금·지켜 준 단계는 남긴다 |

## 10. 결제를 켜기 전에 할 일 (사용자)

1. Play Console: 수익 창출 설정(판매자 계정·세금·정산 계좌) → 인앱 상품 `full_unlock` 비소모성, ₩4,900 / $3.99 등록 → 활성화.
2. App Store Connect: 유료 앱 계약·세금·은행 → 비소모품 `full_unlock` 등록, 심사용 스크린숏(부모용 화면) 첨부.
3. 라이선스 테스터 계정을 넣고 내부 테스트 트랙에서 실제 결제·보류·취소·복원·재설치를 해 본다. **INTERNET 없는 release 빌드로 결제가 되는지 여기서 확인한다**(7절).
4. 데이터 안전성·가족 정책 선언·스토어 설명의 "인앱 결제 없음"을 고친다(`RELEASE.md` 7절, 8절).
5. 위가 끝나면 `kBillingEnabled = true`로 바꾸는 커밋을 따로 만든다(이 문서 날짜와 결정을 기록).
